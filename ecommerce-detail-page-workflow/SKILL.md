# Ecommerce Detail Page Workflow

从一张或多张产品图快速完成产品文案、最小素材组、分屏详情页和无损长图。

**核心原则：收到产品图后只问发布平台；有信息直接生素材，缺信息先交付文案确认稿；整套只保留一个必要确认节点。**

## Fast routes

先读 `references/workflow.md`。默认使用 LEAN；主图任务和局部修改不要进入完整详情页流程。

| 路线 | 触发条件 | 处理 |
|---|---|---|
| 主图快捷路线 | 5 张商品主图、方图、首图套图 | 只生成主图，不进入完整详情页流程 |
| PATCH | 修改、重绘、改规格、替换某屏 | 只重开受影响页面，不得重跑已确认阶段 |
| LEAN | 新建完整详情页；默认使用 LEAN | 按下方快速 SOP 完成交付 |
| STRICT | 用户明确要求正式审查或完整证据包 | 在 LEAN 结果上增加证据和过程文件 |

## Fast SOP

1. **产品图入口**：收到产品图后只询问发布平台，例如“这套详情页准备发布到哪个平台？”不得批量追问品牌、卖点、规格、人群、风格等问题。用户回答后用一句话确认平台。
2. **信息分流**：平台确认后判断产品信息是否充足。
   - **有详情页信息和产品图片**：用户已提供名称/型号、关键卖点和与品类相关的必要规格时，跳过调研，直接进入白底精修和多角度细节生成，不再设置文案确认节点。
   - **没有产品信息或信息不足**：调研小红书和其他平台，结合可见产品事实整理一份详细的 `详情页文案确认稿.md`，交付给用户确认。确认前不得生成白底精修或扩展素材。
3. **最小素材组**：文案已有或已确认后，默认 3 张素材组：`白底精修主图`、`多角度组合图`、`细节组合图`。一次定义三张图的身份约束并连续生成，不逐张等待用户确认；不得扩展为更多前置素材，除非产品结构确实无法被三张分组图覆盖或用户明确要求。
4. **向下推进**：用确认文案与素材完成 6–8 屏策划；每屏承担不同购买问题、机位和画面证明。使用一份统一视觉/身份块加分屏差异，Image2 逐屏生成。
5. **客观纠错门槛**：只在字体崩溃或画面崩溃时定向重绘一次；未出现字体崩溃或画面崩溃就直接输出。画面具体的效果和质量交给用户判断；不自动评价设计感、高级感、构图偏好、配色或吸引力。
6. **完整交付**：保留独立分屏，用 `scripts/stitch_long_page.py` 无损拼接长图，交付素材组、分屏、长图和紧凑执行清单。

## Detailed copy research branch

没有产品信息时，研究目标是补足详情页内容，不是堆积竞品资料。优先使用：用户图片可见事实、品牌/产品官方资料、目标平台同类商品、小红书内容、其他主流电商平台。公开互动信号只是代理指标，不是平台官方排名。

`详情页文案确认稿.md` 至少包含：产品定位、标题/副标题、核心卖点、目标人群与场景、规格/适配、结构或成分信息、使用步骤、包装清单、6–8 屏上屏文案、待确认事实、禁止使用的无依据宣传和来源链接。第三方同款描述只能作为候选信息；无可靠依据的参数必须标记待确认，不得伪装成该产品事实。

用户确认文案后直接进入最小素材组生成，不再重复调研或询问风格。若研究时已得到可用视觉规律，继续复用；否则按目标平台和品类使用一次聚焦调研结果，不另设确认节点。

## Speed controls

- 产品信息齐全：零调研、零文案确认，直接生成 3 张素材组。
- 产品信息不足：只增加一次 `详情页文案确认稿` 确认。
- 不逐张确认白底图、多角度图、细节图或分屏图。
- 不重复保存 N 份统一提示词，不默认创建调研报告、逐屏提示词或审查报告。
- 默认不创建过程报告；缺信息分支只交付一份文案确认稿，完整交付只保留紧凑执行清单。
- 无参考时默认 6–8 屏；不能新增购买理解的页面不生成。
- 用户反馈通过 PATCH 处理，只改指定内容。

## Identity and evidence boundary

真实产品源图是最高优先级依据。AI 衍生可确认角度只能改变可见几何支持的轻微机位、景别和微距；不得虚构背面、底部、内部、被遮挡接口或隐藏结构。尺寸、材质成分、性能等级、认证、检测结果、医疗功效、环保和绝对承诺需要可靠依据，否则标记待确认或省略。
